# Обновленная система классификации отделений ФССП по городам

## Общее описание

Ранее система классификации отделений ФССП по городам использовала жестко закодированный массив известных городов Свердловской области. Теперь система была расширена для поддержки всех регионов Российской Федерации.

## Новая архитектура

### Структура хранения данных

Все данные об известных городах теперь хранятся в формате JSON в папке `backend/dataBase/knownCities/`. Каждый файл соответствует одному региону и имеет имя в формате `{код_региона}.json`.

Пример структуры файла `66.json` (Свердловская область):
```json
{
  "regionCode": 66,
  "regionName": "Свердловская область",
  "cities": [
    "Туринская Слобода",
    "Каменск-Уральский",
    "Нижний Тагил",
    // ... остальные города
  ]
}
```

### Механизм работы

1. При инициализации парсера указывается регион для парсинга
2. При извлечении города из адреса вызывается метод `loadKnownCitiesForRegion()`
3. Метод загружает JSON файл с известными городами для указанного региона
4. Алгоритм извлечения города работает с загруженными данными

### Преимущества новой системы

1. **Масштабируемость** - легко добавлять новые регионы
2. **Гибкость** - можно обновлять списки городов без изменения кода
3. **Поддерживаемость** - данные отделены от логики
4. **Универсальность** - работает для всех регионов РФ

## Использование

Для добавления поддержки нового региона:
1. Создать JSON файл в папке `backend/dataBase/knownCities/` с именем `{код_региона}.json`
2. Заполнить файл списком известных населенных пунктов региона
3. **ВАЖНО**: Расположить названия в порядке убывания длины (от самых длинных к самым коротким)
4. Система автоматически начнет использовать этот список при парсинге

Пример создания файла для Краснодарского края (код 23):
```json
{
  "regionCode": 23,
  "regionName": "Краснодарский край",
  "cities": [
    "Приморско-Ахтарск",
    "Славянск-на-Кубани",
    "Горячий Ключ",
    "Белореченск",
    "Геленджик",
    // ... остальные населенные пункты
  ]
}
```

## Алгоритм извлечения города

Алгоритм извлечения города из адреса остался практически без изменений, но теперь он работает с динамически загружаемыми списками городов:

1. Поиск по префиксу ("г.", "город", "с.", "п.")
2. Поиск известного города в строке
3. "Грязный" поиск по частичному совпадению

При этом теперь каждый регион имеет свой список известных городов, что значительно повышает точность классификации.

## Динамическая настройка региона

Все методы класса FSSPParser теперь используют динамическое название региона:
- `groupDepartmentsByCity()` - формирует результат с правильным названием региона
- `getTestRegionData()` - генерирует тестовые данные для выбранного региона
- Обработка ошибок в `groupDepartmentsByCity()` - возвращает данные с правильным названием региона

Это позволяет системе корректно работать с любым регионом РФ, а не только со Свердловской областью.

## Важное замечание о сортировке

Для корректной работы алгоритма извлечения городов **ОБЯЗАТЕЛЬНО** соблюдать следующее правило:
- Все названия населенных пунктов в JSON файлах должны быть расположены в порядке **убывания длины** (от самых длинных к самым коротким)

Это необходимо для предотвращения ложных срабатываний, когда более короткое название является подстрокой более длинного названия. Например:
- "Туринская Слобода" (15 символов) должно идти перед "Туринск" (7 символов)

Если этого не сделать, алгоритм может неправильно определить город, найдя совпадение с более коротким названием, которое является подстрокой более длинного названия.

## Расширение на все типы населенных пунктов

В отличие от первоначальной версии, которая включала только города, новая система включает:
- Города
- Поселки городского типа
- Села
- Деревни
- И другие типы населенных пунктов

Это позволяет более точно классифицировать отделения ФССП, которые могут находиться не только в крупных городах, но и в небольших населенных пунктах.

## Регионы с особым статусом

Некоторые регионы имеют особый статус из-за нестандартной структуры сайтов ФССП или отсутствия данных:

### Республика Алтай (код 04)
- **Статус**: Парсинг запрещен
- **Причина**: На сайте ФССП отсутствуют необходимые данные
- **Решение**: Используются вручную введенные данные

### Республика Калмыкия (код 08)
- **Статус**: Парсинг запрещен
- **Причина**: Нестандартная структура сайта (использует нумерованные списки вместо таблиц)
- **Решение**: Используются вручную введенные данные из файла `08_Respublika_Kalmykiya.json`
