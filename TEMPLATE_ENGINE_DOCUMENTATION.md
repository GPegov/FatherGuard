# Документация по шаблонизатору FatherGuard

## 1. Назначение шаблонизатора

Шаблонизатор FatherGuard предназначен для автоматической генерации формализованных жалоб в формате HTML на основе данных из документов. Он позволяет создавать официальные жалобы в различные государственные органы с соблюдением установленных форм и требований.

Основные функции шаблонизатора:
- Автоматическая генерация жалоб на основе шаблонов
- Поддержка различных типов государственных органов (ФССП, другие ведомства)
- Форматирование жалоб в профессиональном стиле с соблюдением юридических требований
- Создание приложений к жалобам с автоматической нумерацией
- Генерация PDF-совместимого HTML для последующей печати

## 2. Архитектура интеграции EJS в проект

Шаблонизатор интегрирован в проект через сервис `ComplaintService` в файле `backend/services/complaintService.js`. Используется библиотека EJS для рендеринга шаблонов.

### Компоненты интеграции:

1. **Шаблоны** - находятся в директории `backend/templates`
2. **Сервис обработки** - `ComplaintService` в `backend/services/complaintService.js`
3. **Механизм выбора шаблона** - метод `getTemplatePath()`
4. **Подготовка данных** - метод `prepareTemplateData()`
5. **Рендеринг** - метод `renderComplaintTemplate()`

### Поток данных:
```
Данные документа → prepareTemplateData() → Рендеринг EJS → HTML жалоба
```

## 4. Инструкции по использованию шаблонов

### Создание новой жалобы:
1. Подготовьте данные документа в формате, совместимом с `ComplaintService`
2. Вызовите метод `generateUnifiedComplaint(db, requestData)`
3. Получите результат с полями `content` (текстовая версия) и `templatedContent` (HTML версия)

### Кастомизация шаблонов:
1. Для изменения дизайна отредактируйте CSS в теге `<style>` в шаблоне
2. Для изменения структуры отредактируйте HTML-разметку
3. Для добавления новых полей данных:
   - Добавьте поле в метод `prepareTemplateData()`
   - Используйте его в шаблоне через `<%= fieldName %>`

## 5. Описание API для генерации жалоб

### Основной метод:
```javascript
async generateUnifiedComplaint(db, requestData)
```

**Параметры:**
- `db`: объект базы данных lowdb
- `requestData`: объект с данными для генерации жалобы

**Структура requestData:**
```javascript
{
  documentId: 'string',        // ID документа в БД (опционально)
  agency: 'string',            // Название ведомства
  currentDocument: {           // Данные основного документа
    originalText: 'string',
    summary: 'string',
    keySentences: ['string'],
    violations: ['string'],
    documentDate: 'string',
    senderAgency: 'string'
  },
  relatedDocuments: [          // Массив связанных документов
    {
      // Структура аналогична currentDocument
    }
  ]
}
```

**Возвращаемое значение:**
```javascript
{
  id: 'uuid',                  // ID жалобы
  documentId: 'string',        // ID документа
  agency: 'string',            // Ведомство
  content: 'string',           // Текстовая версия жалобы
  templatedContent: 'string',  // HTML версия жалобы
  relatedDocuments: ['uuid'],  // Массив ID связанных документов
  status: 'draft',             // Статус жалобы
  createdAt: 'ISODate',        // Дата создания
  updatedAt: 'ISODate',        // Дата обновления
  analysis: {                  // Результаты анализа
    violations: ['string']
  }
}
```

## 7. Рекомендации по расширению функционала

### Добавление новых типов шаблонов:
1. Создайте новый EJS файл в директории `backend/templates`
2. Добавьте логику выбора в метод `getTemplatePath()` в `ComplaintService`
3. При необходимости дополните метод `prepareTemplateData()` новыми полями

### Расширение данных для шаблонов:
1. Добавьте новые поля в методе `prepareTemplateData()`
2. Обновите структуру данных в шаблонах
3. Добавьте соответствующие проверки на существование данных в EJS

### Настройка стилей:
1. Измените CSS в теге `<style>` в шаблонах
2. Для печати рекомендуется использовать единицы измерения `cm` и `pt`
3. Добавьте классы для разбиения на страницы при необходимости

## 8. Возможные ошибки и способы их устранения

### Ошибка: "Шаблон не найден"
**Причина:** Неверный путь к файлу шаблона
**Решение:** 
- Проверьте наличие файлов в директории `backend/templates`
- Убедитесь, что имена файлов соответствуют ожидаемым (`fssp-complaint.ejs`, `official-complaint.ejs`)

### Ошибка: "EJS ошибка компиляции"
**Причина:** Синтаксическая ошибка в шаблоне
**Решение:**
- Проверьте синтаксис EJS тегов в шаблоне
- Убедитесь, что все JavaScript выражения корректны
- Проверьте парность открывающих и закрывающих тегов

### Ошибка: "Недостаточно данных для генерации"
**Причина:** Отсутствуют обязательные поля в данных
**Решение:**
- Проверьте, что все обязательные поля присутствуют в объекте данных
- Добавьте значения по умолчанию в шаблоне для опциональных полей
- Используйте проверки на существование данных в шаблоне

### Ошибка резервного механизма
**Причина:** Сбой в генерации как через AI, так и через шаблон
**Решение:**
- Проверьте логи для определения причины сбоя
- Убедитесь, что запасной текстовый вариант корректно формируется
- Проверьте работу файловой системы (права доступа, место на диске)

## Заключение

Шаблонизатор FatherGuard обеспечивает гибкую и надежную систему генерации официальных жалоб. Его архитектура позволяет легко расширять функционал, добавлять новые типы шаблонов и адаптировать под различные государственные органы. Система обладает встроенным механизмом отказоустойчивости и резервными способами генерации, что делает её надежной в production среде.
